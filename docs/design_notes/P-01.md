# Design Note P-01: Emergency Alert Snooze Toggle Fix
**Problem:** In Profile, "Pause Emergency Alerts" cannot be switched off once enabled due to `ProfileModel.copyWith` ignoring `null`, `ProfileMeView.get` omitting snooze fields, and lack of explicit off support in the snooze endpoint.
**Approach:**
1. Backend: Update `donor_snooze_view` and `ProfileMeView` to accept explicit off flags (`off=True`, `enable=False`, `days=null/0`), clear `alert_pause_until` and `emergency_alerts_paused_until`, and include snooze timestamps in `ProfileMeView.get()`.
2. Frontend: Fix `ProfileModel.copyWith` using explicit null-clearing (`clearAlertPauseUntil` / sentinel). Add error rollback in `ProfileNotifier.setSnooze` so failed API calls revert UI state.
3. UI: Full-width button with capsule radius (50) below Impact, showing remaining duration (days/hours/minutes). Provide duration choices in days/months.
**Data Flow:**
- Turn Off: User taps toggle/Resume -> `setSnooze(enable: false)` -> PATCH `users/me/snooze/` (`{"enable": false, "days": null}`) -> server sets `alert_pause_until = null` -> returns 200 with null timestamps -> client clears state -> Wave engine immediately includes donor.
- Restart: App loads -> `ProfileMeView.get` returns `alert_pause_until` -> persists state across restart.
**Failure Cases:**
- Network failure / 5xx: `setSnooze` rolls back UI state to previous value and displays SnackBar error.
- Invalid input: Server rejects non-integer/non-boolean days with 400 without mutating database.
