# Design Note P-09: FCM Push Notification Verification End-to-End
**Problem:** FCM push was never audited end-to-end; login didn't trigger device registration, send paths lacked unified push calls, and deep linking was incomplete.
**Approach:**
1. Token Lifecycle: Ensure `/api/users/update-fcm/` is `IsAuthenticated`. On Flutter login, invoke `updateFCMToken()`; on token refresh, re-post; on logout, revoke `UserDevice` (`fcm_token=None`) and clear `DonorProfile.fcm_token`.
2. 7 Send Paths: Centralize in `notify.py` (new request/wave, donor accepted, chat message, tracking events, standby, closing, thanks). All use channel `bloodpulse_urgent_alerts`, notification + data payloads, respect quiet hours/snooze, log in-app audit.
3. Firebase Admin: Support split `FIREBASE_SERVICE_ACCOUNT_*` assembly without logging secrets; clean UNREGISTERED tokens on both models.
4. App States & Deep Links: Map 7 types across foreground (banner + overlay), background, and terminated tap handlers in `fcm_service.dart`.
5. Command: `send_test_push <user_id>` supports positional user ID, dry-run default, `--confirm` to send.
**Data Flow:** Event -> `notify.py` -> `send_push_to_user` -> Firebase Admin multicast -> Device OS -> `fcm_service.dart` -> `handlePayloadRouting` -> GoRouter.
**Failure Cases:** No tokens (no-op), bad/unregistered token (cleared from DB), expired JWT on logout (fallback to refresh token for revocation).
