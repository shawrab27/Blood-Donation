# Design Note: H-01 Registration 500 & Atomicity Fix
**Problem:** POST /api/donors/ crashes with 500 (unexpected kwarg 'password' in DonorProfile.objects.create) leaving orphan User rows; Flutter catches 500 and falsely navigates to feed; FCM posts /api/users/update-fcm/ before auth causing 401; upazila search needs verification.
**Approach:** Pop 'password' in DonorProfileSerializer create/update; wrap registration in transaction.atomic(); hash password on User only; enforce duplicate phone/email 400 checks; return 201 without password in response; in Flutter, fail on non-2xx and block navigation; guard FCM update-fcm until authenticated; audit upazilas in dev DB.
**Data Flow:** Client POST /api/donors/ -> DonorProfileViewSet.create validates payload -> transaction.atomic() creates User with set_password(raw_password) -> serializer.save(user=user) creates DonorProfile (without password kwarg) -> JWT tokens + profile returned (201). Client saves tokens, stays on form on error, calls updateFCMToken only after successful auth.
**Failure Cases:** Duplicate phone/email -> 400 Bad Request; invalid password (<6 chars) -> 400 Bad Request; DB failure during profile create -> atomic rollback of User (zero orphans); non-2xx response -> Flutter displays error snackbar and stays on registration screen.
