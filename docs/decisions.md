# BloodPulse FINAL DECISIONS (owner-approved; these override any older doc or code)
SCOPE: nationwide Bangladesh, 64 districts, no single-institution wording. Privately tested. Student institution field stays as normal data.
PROTECTED (do not remove or restyle): splash+intro video, language select, 3-slide onboarding (text unchanged), 5-tab navbar, Feed, Health Hub, Chat, requisition-slip upload + Verified Medical Need badge (owner already designed them).
COOLDOWN: 90 days, single source api/conf.py DONOR_COOLDOWN_DAYS, never hard-code. Female/low-iron wording stays neutral until a doctor confirms (do not cite DGDA/WHO numbers).
AUTH: no OTP on login or registration. Registration has intent selector [Donate & Request Blood] (default) / [Only Request Blood] above submit. Google Sign-In lands on /feed; Blood Hub, Communities, Profile tap with incomplete profile -> popup -> existing registration form prefilled (name, email). Server computes profile_complete; client uses it. Civilian NID field removed from registration.
OTP: only at request submit (Create Poster / Confirm Submit -> OTP page: Email works; WhatsApp and Phone show "Coming soon") and forgot-password (email -> OTP -> new+confirm password). Server-side: HMAC-hashed OTP, 10 min expiry, 5 attempts, 60 s resend, throttles by email+IP, single-use 15-min submit token required by the request-create endpoints, no account enumeration, revoke refresh tokens after reset.
GUEST: Welcome screen with anonymized nearby-donor map (coarse cells, min 3 donors) + Quick Actions; every action and locked tab shows the registration popup; Feed and Health Hub stay browsable.
REQUEST: Self vs Proxy (proxy needs attendant name+mobile; donor sees attendant number after Accept). Donor Support Status dropdown (can support / voluntary only with "Voluntary Only / Charity" tag). Units stepper 1-5, locked after post, units_needed/received/pending, two-sided confirmation, auto-close, rate limit with retry_after. Report Broker button. No VIP promises; only "Refreshment provided after donation" for verified partner hospitals. No feed request cards or new request-detail screens.
PRIVACY: donor search by blood group + district only; cards show ONLY district, donor name, blood group, platform tier before Accept. Fuzzed coordinate computed once (deterministic), stored, never re-randomized. Double-blind until MATCHED. No NID collection.
WAVE: ladder 5 -> 25 -> 100 -> 1000 km (env-configurable), our own DB for distance, OSM only for tiles and matched-pair routing, batch FCM 500, per-step cap, quiet hours 22:00-07:00 Asia/Dhaka (critical bypasses), 30-day snooze toggle in Profile after Basic Info.
TRUST: private donor review (1-5 + tags) only from confirmed donations, requester never sees it, trust-score quarantine only after >=2 reviews; day-after check-in push; certificate; poster footer "Generated via BloodPulse". Wording "Donations completed".
COMMUNITIES: National = group details + call blood contacts; Local = clubs division-wise with President/GS/Treasurer/VP; phone shown only if show_contact and verified_by_admin. No member dashboard.
PULSEAI: server-decided personal guard, 90-day answers from server data, never list donor identities, Bangla voice in/out, fare as a RANGE with disclaimer.
ENGINEERING: additive migrations only, one linear chain, never edit applied migrations, never migrate production, old app builds must keep working, no mock data, no overflow at 320x568/360x800/412x915 and text scale 1.3, report raw test output, never write "done" without evidence.
